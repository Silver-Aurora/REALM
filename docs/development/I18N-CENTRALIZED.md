# 全文本 i18n 集中管理实施规范

> 文档性质：实施规范，不记录当前完成进度。当前进度只以根目录 [`STATUS.md`](../../STATUS.md) 为准。
> 视觉约束一律以 [`../design/UI-DESIGN.md`](../design/UI-DESIGN.md) 为准；文风系统契约以 [`WORLD-STYLE-SYSTEM.md`](./WORLD-STYLE-SYSTEM.md) 为准。

## 1. 三层文本边界（核心契约）

| 层 | 内容 | 组织方式 | 语言来源 |
|---|---|---|---|
| 一 · 界面固定文本 | 登录页、按钮、面板标题、报错、空态 | 界面 i18n key（`modules/i18n/`） | 用户级界面语言设置 |
| 二 · 世界内系统文本 | 批次 P 的 26 个 key（司卷提问、文风选项名、行动卡、场景定格、卷首空态） | 风格 × 语言模板（4 × 3） | 界面语言设置（语言维度）+ 世界 style（风格维度） |
| 三 · 动态文本 | 玩家输入 + AI 生成 | **绝不进资源文件** | 跟随玩家输入语种（prompt 约束，不做服务端语种检测） |

## 2. 语言枚举与解析

- `UiLanguage = "zh-CN" | "en" | "ja"`；默认 `zh-CN`。
- 解析顺序：用户级设置（accounts.ui_language）→ 默认 zh-CN。
- 缺失 key fail-closed：回落 zh-CN 并 `console.warn` 记录；**绝不向用户暴露裸 key**。

## 3. 存储

- 迁移 0015：`accounts` 增加 `ui_language text NOT NULL DEFAULT 'zh-CN'`（CHECK 限定三语枚举），realm_runtime 授 `UPDATE (ui_language)`。
- `GET /api/auth/me` 返回 `uiLanguage`；`POST /api/settings/language { language }` 保存（门禁与既有 API 一致）。
- 设置页提供三语切换纸签，保存即生效（前端全局语言状态随保存更新）。

## 4. key 命名规则

- 界面层：`ui.<模块>.<语义>`（如 `ui.composer.submit`、`ui.login.title`）。
- 第二层沿用批次 P 的既有 key 不变（向后兼容），仅扩语言维度。

## 5. 界面层 key 清单（逐模块）

| 模块 | key 前缀 | 覆盖内容 |
|---|---|---|
| 登录页 | `ui.login.*` | 标题、副题、令牌/昵称标签、主动作、错误提示 |
| 顶栏与导航 | `ui.header.*` / `ui.nav.*` | 世界库/设置入口、视角与同步状态、导航分区标题与「当前/阅读中」标签 |
| 记录页 | `ui.record.*` | 当前记录 eyebrow、错误/加载态、通知关闭、记录代码前缀 |
| 时间线 | `ui.timeline.*` | 可见性标签（公开/同场/限定/仅你/本地待提交/OOC）、角色标签（旁白/玩家/规则/角色）、预览卡提示 |
| 输入区 | `ui.composer.*` | 你的行动、占位、送出/处理中、行动触发、已选行动、快捷键提示 |
| 行动面板 | `ui.affordance.*` | 面板标题、副题、四层分组名、关闭 |
| 提案区 | `ui.suggestion.*` | 区域标签 |
| 可见性确认 | `ui.visibility.*` | 标题、说明、两个决策按钮、取消 |
| 场景检查器 | `ui.inspector.*` | 场景/阵容/记忆卡片标题、进行中、视角说明、未开放提示、记忆深度三档、整理摘要 |
| 世界库 | `ui.library.*` | 标题、关闭、图谱入口、启笔铸界标题/提示/起草/手稿/落笔/重起草、工笔细琢、手动表单标签与提交、文风切换 aria |
| 司卷问答框架 | `ui.guided.*` | 标题、退出、留白跳过/落墨/AI 代笔/斟酌中、同行者与场景的说明行、就这些/留白独行/全部留白/场景已定、已定之卷、入卷之名 |
| 知识图谱 | `ui.graph.*` | 面板标题、下钻、编辑、审核操作文案 |
| 设置页 | `ui.settings.*` | 模型设置全部表单标签/按钮/提示 + 界面语言区块 |

覆盖率断言：注册表 key 集三语完全一致、无空串；前端源码扫描不允许 JSX 文本节点残留硬编码中文（白名单：`aria-hidden` 装饰符与模板插值片段）。

## 6. 第二层三语化

- 批次 P 的 26 key × 4 风格扩为 × 3 语言（`zh-CN / en / ja`），en/ja 按自然语感重写（ja-classical 用日语古风措辞，en-western_fantasy 用史诗腔），不机械直译。
- 契约测试断言 26 × 4 × 3 全格无空串；`worldStyleText(key, style, params, language)` 语言参数缺省 zh-CN。
- 第二层语言跟随界面语言设置；风格维度跟随世界 style，两者正交。

## 7. 第三层动态文本

- 回合管线（DM/旁白/角色/复核/可见性评估）、提案、结晶、司卷代笔、创世手稿的系统 prompt 统一追加：「回应语言必须与玩家输入保持一致（玩家用中文则中文，用英文则英文，用日文则日文）。」
- 玩家输入一律原样展示，不做任何改写或检测。

## 8. fail-closed 矩阵

| 环节 | 失败形态 | 行为 |
|---|---|---|
| 语言解析 | 非法/缺失语言值 | 按 zh-CN |
| 界面 key 查找 | key 缺失 | 回落 zh-CN 并告警；zh-CN 也缺则抛出（契约测试兜底） |
| 第二层模板 | 语言缺失 | 回落 zh-CN 同风格 |
| 语言保存 | 网络/服务端失败 | notice 提示，界面保持当前语言 |

## 9. 验收标准

1. Core 契约：三语 key 集一致、缺失回落、26×4×3 全覆盖无空串。
2. PG 集成：语言设置持久化与默认 zh-CN。
3. 模型探针：中文输入→中文回复、英文输入→英文回复，样例进交付报告。
4. GUI Q 组：界面切换 en/ja 后固定文案与世界内系统文本同步切换且风格维度保持、动态文本不受影响、缺失 key 不暴露裸 key、玩家输入原样展示；既有组全量回归。
