# 界核 / REALM GUI 交互测试计划

> 文档性质：测试设计与验收约定，不是当前通过状态；执行证据以当前代码上的命令原始输出为准。
> 执行方式：`scripts/test-gui-with-scratch.mjs` 启动隔离 PostgreSQL、Web 服务与 Playwright state。
> 当前用例清单以 `tests/gui/*.spec.ts` 为准；不要将 `--list` 数量当作执行结果。

## 0. 运行环境与安全边界

| 项 | 当前规则 |
|---|---|
| 应用地址 | runner 动态分配 loopback 端口；不复用常驻 `realm-dev.service` |
| PostgreSQL | 每次由 `scripts/test-gui-with-scratch.mjs` 启动 disposable PG17 集群并应用完整迁移链、seed demo；不连接共享 `realm_dev` |
| Playwright state | auth state、输出目录和项目锁均为本次运行独立临时目录 |
| 模型 | **默认离线确定性**：runner 在应用启动前拉起 `tests/helpers/fake-openai-provider.mjs`（只绑 127.0.0.1 临时端口，阶段注册表指纹分发固定 fixture，未知阶段 fail-closed 422，日志不记 prompt/header/key/body），并向被测应用显式注入 `REALM_MODEL_PROVIDER=custom-openai` + loopback `/v1` + 确定模型 id + 空 key；不读宿主 `.local` 模型设置、不透传宿主凭据 |
| 默认命令 | `npm run test:gui`（Chromium）/ `npm run test:gui:webkit`；默认命令不触任何真实 provider |
| 清理 | runner `finally` 停止独立服务、删除仅由它创建的容器和临时目录；完成后仍需核查无残留 |
| 演示记录 | `record_first_watch` 仅用于 scratch seed 内只读冒烟，不代表真实库被访问 |

不得直接对默认 `playwright.config.ts` 执行写入型 `npx playwright test`：配置可能连接共享服务/数据库。若 runner 隔离探针失败，立即停止，不得回退共享环境。

## 1. 测试目标

覆盖 STATUS.md 已记录的全部前端可交互特性，用真实浏览器验证：

1. 世界库（创建世界/故事/记录、世界线、timeline 标签）
2. 记录页（事件时间线、语义段渲染、消息提交、乐观更新、失败恢复）
3. 行动面板（技能/物品/姿态/场景行动、能力选择、草稿预填）
4. 可见性确认（密谋预判、发送前确认卡片、受限受众）
5. 场景检查器（角色记忆、三档深度、关系线索、整理摘要）
6. 模型设置页（发现/选择/连接测试/think 开关）
7. 实时同步（SSE 已提交事件、断线回补）
8. 响应式（桌面三栏/平板双栏/手机纵向）
9. 纸墨设计语言（直角、语义色、无圆角）
10. Safari/WebKit 视口与窗口行为（100dvh 回退、-webkit-fill-available、文本缩放保护、滚动/弹层/键盘）

## 2. 测试方法

- 每个用例：前置 → 操作步骤 → 预期结果；需要写入时断言 UI 状态与 scratch DB 中的持久化结果/事件，不只看 DOM。
- **测试数据隔离**：创建型用例只写入本次 disposable PostgreSQL；不可用唯一命名替代隔离。runner 销毁本次容器和临时目录，运行后还需确认无残留。
- 断言尽量落在用户可见状态、角色/可访问名称及持久化结果上，不依赖固定序号或内部实现细节。
- Chromium 是默认主测；WebKit 视作 Safari 引擎近似，选定关键旅程复跑。不把 `--list` 或计划矩阵当成已执行证据。
- **模型依赖分层（已实现）**：默认 GUI 回归完全离线——fake provider 提供 `/v1/models` 与 `/v1/chat/completions`（stream/non-stream）与阶段 fixture（visibility/plan/review/narrator/character/presence/连接探针/场景结晶/司卷对谈/初夜/创世手稿/分步代笔）；初夜的 characters 按生产要求从请求同行者名单 derive，分步代笔按 [Task for this step] 七步分发。`u2-fake-provider-turn.spec.ts` 是全链玩家回合 tracer。契约测试：`tests/fake-openai-provider.test.mjs`（13/13）。注意：记忆萃取是纯 SQL 管线（无模型调用）；技能证据阶段未注册（默认旅程不触发 use_skill 工具调用）。
- **真实模型 smoke**：`tests/gui/f-real-provider-smoke.spec.ts`（原 F1–F4 的 OpenRouter 部分）只在 `REALM_ENABLE_REAL_PROVIDER_SMOKE=1` 时运行（`npm run test:gui:smoke:real-provider`）；runner 仅在该模式透传宿主模型环境变量且绝不打印值；默认跳过，不进 `npm test`。模型结果不稳定时必须报告，不吞红，也不阻塞确定性 UI 回归。

2026-09-27 修复前全量基线：scratch Chromium 124 项，69 passed / 55 failed / 0 skipped，退出码 1（21.3m）。其后同一组 17 项确定性 focused GUI 在 Chromium、WebKit 分别 17/17 通过，WebKit z2 邀请流程另 1/1 通过；这不代表 provider-dependent 全量或 ComfyUI 真实生成已通过。

## 3. 用例清单

### A. 世界库（Library）

**A1 初始加载**
- 打开 `/`，世界库面板可见，列出演示世界“烬海诸国”。
- 世界条目显示名称、纪元、摘要、状态。

**A2 创建世界**
- 新建世界（唯一名称），提交后出现在列表；世界自动获得原初世界线。

**A3 创建故事**
- 在目标世界下创建故事（唯一名称），提交后出现在该世界的故事列表。

**A4 创建记录并进入**
- 创建记录（唯一名称），提交后记录出现在列表；点击记录进入可玩状态。
- 新记录自动装配：默认玩家 + 两名 AI 角色 + 场景 + 公开可见性策略（可在页面中看到角色存在）。

**A5（旧入口已退役）**
- 历史计划曾假设世界库有独立的分支创建 tab；当前界面已移除该入口，不再用 API `/api/worldline/conflict` 冒充用户旅程。
- 当前分支 UI 旅程由 `tests/gui/v-branch.spec.ts` 覆盖；V1 已在最新 focused scratch Chromium 运行通过，V2/V3 与 WebKit 仍待复验。

**A6 timeline 标签**
- 创建回溯记录（Retrospection）或查看 Merge 记录时，记录项显示对应标签（`Retrospection` / `Merged`）。
- 普通记录显示主时间线标签（或等价标识）。

### B. 记录页交互

**B1 时间线加载**
- 打开演示记录 `record_first_watch`，已提交事件按序显示，正文完整可见。

**B2 语义段渲染**
- 事件正文五类语义段（环境/剧情/关键事实/动作/台词）只以文字颜色区分：
  - 环境 `--semantic-environment`（#3f6770）
  - 剧情 `--semantic-story`（#70556b）
  - 关键事实 `--semantic-fact`（#8a672d）
  - 动作 `--semantic-action`（#526b50）
  - 台词 `--semantic-dialogue`（#9b4938）
- 断言：无语义底色/边框/内边距，正文占满卡片可用宽度。

**B3 自然输入提交**
- 输入普通台词 → 提交 → 201 → 时间线出现新事件，正文为输入内容。

**B4 括号动作 + 台词**
- 输入 `（环顾四周）这里好安静` → 提交 → 事件中动作与台词被正确拆分呈现。

**B5 乐观发送与清理**
- 提交后输入框清空；新事件出现；发送按钮恢复可用。

**B6 失败恢复**
- 提交失败（如暂停服务或构造错误）时：草稿从时间线移除、输入内容恢复、可重试；不出现幽灵事件。

**B7 语义流式呈现**
- 新事件出现后，正文按完整短句逐段显示（M4 语义流式切分器行为）；最终文本完整。

### C. 行动面板

**C1 能力投影**
- 输入框附近显示行动面板，列出当前受权能力（技能/物品/姿态/场景行动，如“细致观察”“雾港信号灯”“警戒姿态”等）。

**C2 选择行动 → 草稿预填**
- 点击某个行动 → 输入框预填对应草稿，可继续编辑。

**C3 提交行动**
- 提交行动草稿 → 正式提交成功；能力选择状态被清理。

**C4 过期行动处理**
- 若行动选择已过期：提交失败不消耗写入授权，用户仍可改用自然输入继续提交（错误提示可见即可）。

### D. 可见性确认

**D1 密谋预判**
- 输入含“悄悄/低声/只告诉/不要让其他人听到”的内容 → 提交 → 出现发送前确认卡片，不直接公开落库。

**D2 确认“仅目标可听”**
- 确认卡片上选择“仅他们可听” → 提交成功（201），事件带受限可见性；确认卡片消失。

**D3 确认“公开发送”**
- 另一条密谋输入选择“公开发送” → 提交成功，事件为公开。

**D4 取消确认**
- 取消确认卡片 → 草稿保留，可修改后重新提交。

### E. 场景检查器

**E1 角色记忆卡片**
- 场景检查器显示当前角色记忆卡片（`角色记忆 / Memory`），内容非空。

**E2 三档深度切换**
- 点击“精简 / 平衡 / 沉浸”切换 → 记忆内容通过真实接口重新读取并刷新；按钮状态正确。
- 窄屏下按钮可换行，不挤压文字。

**E3 关系线索**
- 记忆卡片显示由已知对象推导的关系线索（若有数据）。

**E4 整理摘要**
- 点击“整理摘要”入口 → 出现可触发操作（触发真实模型调用；模型响应成功则摘要写入，失败不视为 UI bug，但交互入口与反馈必须存在）。

### F. 模型设置页

> 当前实现分两档：默认离线确定性用例（`f-settings.spec.ts` 的 F1/F2/F3，
> fake provider 上的基本信息/模型发现/连接测试 + F5/F6 静态与滚动契约）；
> OpenRouter 真实供应商验收（费率/目录/真实连接）在
> `f-real-provider-smoke.spec.ts`，仅 `REALM_ENABLE_REAL_PROVIDER_SMOKE=1`
> 时运行，默认跳过。

**F1 打开与基本信息**
- 进入设置页：显示 LM Studio 与 OpenRouter 两个可保存 profile；当前 active profile 的 baseUrl 与凭证状态正确。
- API key 只显示服务端 hint，不回显完整密钥。

**F2 模型发现与费率**
- 触发模型发现 → 可用模型列表包含模型名、上下文长度、tools/structured outputs 能力与当前输入/输出费率。
- OpenRouter 费率按 Models API 的 USD/token 换算为每 1M token；prompt/completion 均为 0 时标记“当前免费”。
- 模型列表按 20 项分页，支持名称/ID/作者检索与“仅看免费”筛选，筛选不重新请求供应商。

**F3 模型选择与 thinking**
- 每个供应商 profile 独立保存 selectedModel；切换供应商不覆盖另一个 profile。
- OpenRouter 优先选择同时支持 tools 与 structured outputs 的免费模型；LM Studio 保持既有 thinking 语义。
- 设置页显示并保存 `max_tokens` 返回长度预算；调用方显式预算可覆盖 profile 默认值。

**F4 连接测试**
- 连接测试使用当前 profile、当前模型和真实端点；OpenRouter 的结构化探针使用足够的 token 预算，不把 HTTP 200/空正文判为成功。

**F5 数据边界说明**
- 页面明确本地 LM Studio 与 OpenRouter 的数据出站差异，以及最小上下文和 API key 不进入浏览器的边界。

### G. 实时同步

**G1 SSE 实时事件**
- 页面保持打开，通过另一途径（或同页操作）产生新事件 → 时间线自动出现新事件，无需刷新。

**G2 断线回补**
- 暂停服务 → 页面显示重连状态；恢复服务 → 事件回补，时间线连续（如 UI 有连接状态提示则断言该提示）。

### H. 响应式

**H1 桌面三栏**（≥1024px）：世界导航 | 记录主区 | 场景检查器，三栏可见。

**H2 平板双栏**（~900px）：左侧导航 + 主记录，场景检查器移到主记录下方。

**H3 手机纵向**（~375px）：纵向布局，输入与时间线可用，无横向溢出。

### I. 纸墨设计语言

**I1 直角**
- 关键交互元素（卡片、输入框、按钮、弹窗）`border-radius` 为 0 或接近 0（允许内部小元素例外），无胶囊按钮。

**I2 语义色**
- 主动作/玩家轨迹为朱红系；正常/在线为苔绿；等待/秘密为金棕；正文主色 `--ink`。

**I3 硬阴影**
- 主卡片阴影为短距离硬阴影（如 `3px 3px 0` 风格），无大范围模糊漂浮感。

### J. Safari / WebKit 窗口与视口

**J1 视口高度回退**
- WebKit 下页面高度使用 `100dvh` 回退链：`100dvh` → `-webkit-fill-available`，不出现内容被窗口底部裁切或滚动异常。
- 文本缩放保护生效（`text-size-adjust` 等）。

**J2 滚动与布局**
- WebKit 下时间线滚动、弹层（可见性确认卡片）、输入框键盘行为正常，无窗口尺寸跳动。

**J3 窗口 resize**
- WebKit 下从桌面宽度缩到手机宽度再放大：布局正确切换，无残留滚动条或元素错位。

**J4 差异修复**
- 若发现 Chromium 正常而 WebKit 异常的窗口/视口 bug：修复并回归验证（这是本任务重点之一）。

### K. 世界知识图谱与 Canon 审核

**K1–K6**
- 图谱面板打开与节点渲染；下钻 Claim 列表；创建实体与提交 Claim；Canon 审核提案可见/拒绝消失；图谱区域无圆角无半透明卡片。

### L. 启笔铸界与数据隔离

**L1 自然语言创世全流程**
- 世界库「启笔铸界」入口可见、手动录入默认收起；输入灵感 → 纸墨手稿展开 → 微调世界名 → 落笔入界直达新记录；人类玩家绑定登录账号昵称。

**L2 新世界数据隔离与空态留白**
- 手动创建的全新世界：阵容只有当前账号玩家（无塞娜/弥洛/洛川鬼影）；导航与面包屑无演示世界文字残留；场景空字段结构性消隐；地点未定回退为故事名；空时间线卷首意象。

### M. 设定结晶与逻辑一致性裁决

**M1 动态生长**
- 对话中说出新地点与天气 → 结晶管线（提取+裁决+写回）完成后场景面板对应字段浮现，时间线出现「场景定格」事件。

**M2 矛盾裁决**
- 说出时间倒退的矛盾设定；若异步结晶导致 409 `WRITE_CONFLICT`，UI 提示并恢复原文，让玩家确认后重试；确定性 fake provider 仅按 `[Player's exact words]` 区块选择倒退提取与拒绝裁决；最终观察窗口内世界时间保持不变。
